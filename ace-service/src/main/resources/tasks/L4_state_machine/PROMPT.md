# L4 — Order state machine and idempotency (budget 75 min)
Build a service on `localhost:8080` (via `docker compose up`, with PostgreSQL) exposing: `POST /accounts` → 201 `{accountId, currency, availableBalance}`; `GET /accounts/{id}` → 200 `{accountId, currency, availableBalance, reservedBalance}`; `POST /accounts/{id}/deposits` → 200 `{availableBalance}`; `POST /orders` `{accountId, symbol, side, quantity, limitPrice}` → **201** `{orderId, status:"FILLED", executedAt}` (immediate fill, balance debited by quantity × limitPrice) or **422** on insufficient funds; `GET /orders/{id}` → 200 `{orderId, status, side, symbol, quantity, limitPrice}` / 404; `POST /orders/{id}/cancel` → 200 `{orderId, status:"CANCELLED"}` on NEW, **409** on a terminal order; `GET /health` → 200. State machine: `NEW → FILLED | CANCELLED`; `FILLED`/`CANCELLED` are terminal — because orders fill immediately, cancelling a fresh order returns 409.
**Bespoke rule:** `POST /orders` accepts an optional header `Idempotency-Key`; a repeat with the same key within 60 s returns the **same** `orderId` with **200** (not 201) and does not execute twice: balance is identical after the duplicate.
All money is `BigDecimal` or integer minor units — never float/double. Decimal JSON values are strings; timestamps are ISO-8601 UTC with millisecond precision (`2026-01-31T12:00:00.123Z`). Java 21, Spring Boot 3, Gradle, PostgreSQL via Flyway. Ship tests that run with `gradle test` in a clean container: a fresh PostgreSQL is provided through `SPRING_DATASOURCE_URL/USERNAME/PASSWORD` (tests may use it or run in memory; they must not need Docker or the network). Do not edit anything under `task/`. **This rung starts from an empty workspace: everything it names must be built here.**
