## Top Issues

1. **Systemic null-safety gap across the UI layer** (7 files)
   `ExperimentNewView` (uninitialized `monoRules` → NPE on auto-unbox), `ExperimentParams` (null `template` → NPE; `type.cast` → raw `ClassCastException` violating the documented `IllegalArgumentException` contract), `ExperimentsView` (null `status` → NPE in `effective.equals(…)`), `JobStatuses` (`Set.of(…).contains(null)` → NPE from `ImmutableCollections`), `Links` (boxed `Long` null → `String.valueOf` yields `"null"` in route params), `SseEvent` (`payloadType()` returns null for typeless events), and `JobSpecs` (no null guard on `raw`). Each is individually a latent crash; together they indicate the absence of a null-accepting-input convention or `@Nullable` annotations throughout `com.agentbench.ui`.

2. **N+1 sequential HTTP calls on the UI thread** – `ExperimentDetailView.blockedReasons()`
   One blocking HTTP round-trip per blocked job, executed synchronously. For an arm × repeat grid producing 20+ blocked jobs the UI freezes for the full sum of network latencies. No parallelism, no batching endpoint, no progress indicator.

3. **Stale data on re-navigation** – `GroupsView`
   Vaadin caches `@Route` instances per session; `render()` runs only in the constructor, so API data is fetched exactly once and never refreshed. Sibling views (`ExperimentsView`, `JobsView`) re-fetch on re-entry, making `GroupsView` the lone outlier.

4. **Sort/display mismatch in the experiment grid** – `ExperimentsView`
   The status column *renders* the derived effective status (queued → running/blocked) but the *comparator* sorts by the raw table status. Clicking the column header produces a visibly wrong ordering.

5. **Serialization contract broken** – `ServiceProperties`
   The record is stored as a non-transient field in `ServiceClient` (session-serializable) but omits `serialVersionUID`, unlike its siblings `ServiceClient` and `JobLiveState`. Any field reordering or type change silently breaks persisted sessions.

6. **Secret-leak vector** – `.gitignore`
   No `.env` / `.env.*` pattern. API keys or DB credentials placed in a local `.env` can be committed accidentally.

7. **Flaky / vacuous test assertions** – `JobLiveStateTest`, `ServiceClientMappingTest`
   `join(10 s)` in `JobLiveStateTest` never asserts the writer actually terminated, so subsequent `assertEquals` calls race a live mutator. In `ServiceClientMappingTest`, an overly broad `catch (Exception)` masks any transient I/O failure as "unimported," and `runs.get(0)` on an empty list produces a hard `IndexOutOfBoundsException` rather than a clean skip.

8. **UI state desync on init** – `ExperimentNewView`
   `parallel` checkbox is Vaadin-default (enabled) while the `par` checkbox it gates is unchecked; no initial `setEnabled(false)` call. The value-change listener fires only on *subsequent* toggles, so the user sees a dead control on first render.

9. **CSS: images with explicit `height` attribute break responsiveness** – `md-viewer.css`
   CommonMark HTML output emits `<img width="800" height="600">`; `max-width: 100%` alone does not override the pixel `height`, so images render at fixed height and overflow horizontally.

10. **HTML rendering: `String.join("\n", …)` produces invisible separators** – `ExperimentDetailView`
    Browsers collapse consecutive whitespace (including `\n`) in inline `Span` content. Multiple blocked reasons render as a single run-on string.

## Cross-Cutting Concerns

- **Null-input handling is ad-hoc and inconsistent.** Seven production classes in `com.agentbench.ui` each fail differently on null (NPE, CCE, `"null"` string, skipped cleanup). There is no shared `Objects.requireNonNull` guard, no `@Nullable`/`@NonNull` annotation policy, and the Javadoc contracts (`ExperimentParams`) promise `IllegalArgumentException` but the code throws `NullPointerException` / `ClassCastException` instead.
  Representative: `ExperimentParams.java`, `JobStatuses.java`, `Links.java`, `SseEvent.java`.

- **Dead code / unused imports in both production and test files.** Four files carry imports that the compiler/IDE flags as unused (`PreflightView` → `UI`, `SseEvent` → `java.util.List`, `RoutesReflectionTest` → `assertTrue`, `ServiceClientSerializationTest` → `assertNull`). A fifth (`ServiceClientMappingTest`) computes `allGroups` with null-safe logic but never asserts on it.
  Representative: `PreflightView.java`, `SseEvent.java`, `RoutesReflectionTest.java`, `ServiceClientMappingTest.java`.

- **UI lifecycle assumptions not respected.** Vaadin caches `@Route` views; `GroupsView` fetches data once in the constructor and never refreshes. `PreflightView` returns early on exception without resetting the poll interval, leaving a stale 2 s cadence that hammers a downed service.
  Representative: `GroupsView.java`, `PreflightView.java`.

- **Test assertions weaker than the code under test.** `JobLiveStateTest` uses `join(timeout)` without verifying completion; `ServiceClientMappingTest` catches all exceptions as "expected unimported" and dereferences `runs.get(0)` without a length guard. Both will produce false-green or false-red results under CI timing variance.
  Representative: `JobLiveStateTest.java`, `ServiceClientMappingTest.java`.
