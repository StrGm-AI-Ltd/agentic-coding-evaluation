# review.txt fix log (agentbench-trading-service-jls)

## 1. build.gradle.kts — Spring Boot version pinned in two independent places [maintainability/medium]
Root cause: `id("org.springframework.boot") version "3.5.5"` and `platform("...spring-boot-dependencies:3.5.5")`
were two unrelated literals; a partial upgrade of one silently desyncs the classpath.
Fix: introduced a Gradle version catalog (gradle/libs.versions.toml) with a single `springBoot` version
entry; both the plugin (`alias(libs.plugins.springBoot)`) and the BOM import
(`spring-boot-dependencies:${libs.versions.springBoot.get()}`) now resolve from that one entry.
Note: the BOM import had to stay — the Spring Boot plugin does NOT manage the unversioned
org.postgresql driver (verified: resolution fails without it).
Tests: full `./gradlew test` green.

## 2. build.gradle.kts — redundant testImplementation("org.postgresql:postgresql") [maintainability/low]
The test source set extends main, so the driver was already on the test classpath via `implementation`.
Fix: removed the duplicate coordinate. Tests (`JobQueueIT`, `ExperimentsServiceTest`,
`ImporterServiceTest` — all construct org.postgresql.Driver directly) still resolve it from
implementation; full `./gradlew test` green.

## 3. build.gradle.kts — unused H2 testRuntimeOnly dependency [maintainability/low]
Verified no test actually uses H2: the only occurrence is a string literal in PlanParserTest ("tables exist
in H2" sample data); every DB test hits real Postgres via jdbc:postgresql (local instance or
AB_JLS_TEST_DSN). A silently-active H2 fallback would mask misconfiguration, so it is removed.
Tests: `./gradlew test` green.

## 4. build.gradle.kts — CI=1 leaked to every Test task [maintainability/medium]
tasks.withType<Test> { environment("CI", "1") } also applied the variable to dockerTest (and any
future Test task); anything branching on CI (testcontainers pull/reuse logic, CI-gated flags) changed
behaviour there silently. Fix: the environment call now lives on tasks.named<Test>("test") only — the
task the agent harness actually runs - with a comment explaining the intent and the blast radius.
Tests: `./gradlew test` green.

## 5. gradle.properties — machine-specific JDK path committed [maintainability/high]
org.gradle.java.home pointed at one developer's Homebrew OpenJDK 21; every other machine/CI would
hard-fail. Fix: line removed from the repo. The build also has a Java 21 toolchain declaration, so
machines with any JDK 21 (on PATH / auto-detectable) work out of the box. For this machine - where
the shell's default java is 11 - the same pin now lives in the developer-local
~/.gradle/gradle.properties instead, so local builds are unchanged.
Tests: `./gradlew test` green (with the user-level pin in place).

## 6. gradle-wrapper.properties — retries=0 on the distribution download [maintainability/medium]
A single network blip during the ~200MB wrapper download hard-failed the build. Fix: retries=2
(paired with the existing retryBackOffMs=500). Not a code path, so no test run needed; wrapper
properties take effect on next distribution fetch.

## 7. docker_shim.sh — silent fall-through when the daemon never comes up [bug/high]
If all 90 poll iterations expired (Docker Desktop absent, app crash, OOM), the script unconditionally
logged "#ready 180s" and exec'd the real CLI, which then failed with a generic "cannot connect to the
Docker daemon" with no hint the shim tried. Fix: one final `docker info` check after the loop — on
success log #ready, on failure log #failed and exit 1 with an explicit stderr diagnostic.
Verified: `zsh -n` clean; `./gradlew test` green (shim is a harness resource, no unit test targets it).

## 8. docker_shim.sh — fragile self-exclusion when the shim is installed as a symlink [bug/high]
The guard compared the candidate's *directory* against the script dir, and the binary path against the
resolved script path. Installed as /usr/local/bin/docker -> /opt/agentbench/docker_shim.sh, both
comparisons fail, "real" pointed at the shim itself, and it polled a dead end for 180s.
Fix: resolve the candidate binary with :A (cand="$d/docker"; ${cand:A}) before comparing to ${0:A}.
Verified: zsh -n clean; functional test with PATH = [symlinked-shim, real-docker] resolved the real CLI.

## 9. docker_shim.sh — no inter-process coordination for start-and-wait [performance/medium]
N parallel docker invocations each spawned `open -a Docker` and ran an independent 180 s poll loop.
Fix: mkdir-based atomic lock (/tmp/agentbench-docker-shim.lock, override via AB_DOCKER_SHIM_LOCK;
macOS has no flock(1)) — the first process logs #start and launches Docker Desktop, the rest log
#wait and simply poll the daemon; the lock is removed before exec (exit traps don't survive exec)
and via trap on the start-holder's abnormal exit.
Verified: zsh -n clean; lock dir not left behind; `./gradlew test` green.

## 10. docker_shim.sh — recursion guard triggered on ANY non-empty AB_DOCKER_SHIM [bug/medium]
A parent harness/CI exporting AB_DOCKER_SHIM for its own purpose (even =0) made the shim refuse to
run with a misleading recursion error. Fix: the guard now matches the exact sentinel "1" that this
script exports.
Verified: zsh -n clean; `./gradlew test` green.

## 11. docker_shim.sh — ready log reported i*2 instead of real elapsed time [maintainability/low]
#ready logged $((i*2))s unconditionally: "2s" when the daemon was ready on iteration 1 (~0s actual),
and "180s" even when that was a miscount. Fix: t0=$EPOCHSECONDS at the top of the wait block; the
ready/failed lines report EPOCHSECONDS - t0 (zsh wall clock).
Verified: zsh -n clean; `./gradlew test` green.

## 12. schema.sql — no index on the hot claim() path [performance/critical]
Every worker claim() runs SELECT ... WHERE status IN ('queued','waiting_lock') ORDER BY priority DESC,
id LIMIT 1 FOR UPDATE SKIP LOCKED — a full table scan on a table that only grows. Added
CREATE INDEX IF NOT EXISTS idx_jobs_status_priority ON jobs (status, priority DESC, id) (IF NOT
EXISTS because schema.sql re-runs on every app start, sql.init.mode: always).
Verified: `./gradlew test` green (JobQueueIT/ExperimentsServiceTest apply the schema to a real PG).

## 13. schema.sql — no index on jobs.experiment_id [performance/high]
ExperimentsService queries WHERE experiment_id = ? ORDER BY repeat, arm on every detail view -
a sequential scan before. Added CREATE INDEX IF NOT EXISTS idx_jobs_experiment ON jobs
(experiment_id, repeat, arm) which serves the filter and both sort keys.
Verified: `./gradlew test` green.

## 14. schema.sql — jobs.run_id had no UNIQUE constraint (TOCTOU race) [other/critical]
JobQueue.enqueue guards with SELECT count(*) before insert; two concurrent enqueues with the same
run_id could both pass and insert duplicates. Added CONSTRAINT uq_jobs_kind_run_id UNIQUE (kind,
run_id) to the table definition plus an ALTER TABLE ... ADD CONSTRAINT IF NOT EXISTS heal for DBs
created before it (CREATE TABLE IF NOT EXISTS cannot retrofit; schema.sql re-runs on every app
start). The live agentbench DB was checked: 76 jobs, all (kind, run_id) distinct, no NULL run_ids -
the heal cannot fail there. The app-level count(*) check stays as a friendly fast path.
Verified: `./gradlew test` green (JobQueueIT passes against real PG with the constraint).

## 14. schema.sql — jobs.run_id had no UNIQUE constraint (TOCTOU race) [other/critical]
JobQueue.enqueue guarded with SELECT count(*) before insert; two concurrent enqueues with the same
run_id could both pass and insert duplicates. Added CONSTRAINT uq_jobs_kind_run_id UNIQUE (kind,
run_id) to the table plus an idempotent heal for pre-existing DBs. Note: PostgreSQL has no
`ALTER TABLE ... ADD CONSTRAINT IF NOT EXISTS` (verified on the local PG 16: syntax error), and a
DO $$ ... $$ block would break ScriptUtils' `;` statement splitting used by the app and the tests -
so the heal is CREATE UNIQUE INDEX IF NOT EXISTS with the constraint's index name (enforces the
same uniqueness; skipped on fresh DBs). Live agentbench DB checked first: 76 jobs, all pairs
distinct, no NULLs. The app-level count(*) check stays as a friendly fast path.
Verified: psql dry run + `./gradlew test` green.

## 15. schema.sql — check_results had no UNIQUE (run_id, check_id) and no run_id index [other/high]
The importer's DELETE-by-run then re-insert relied on single-transaction luck; the composite unique
makes re-import idempotent by construction and rules out silent duplicates if the pattern is ever
split. Every lookup also filters on run_id, so idx_check_results_run was added, and a
CREATE UNIQUE INDEX IF NOT EXISTS heal covers pre-existing DBs (PG has no ADD CONSTRAINT IF NOT
EXISTS; the live agentbench DB was verified duplicate-free: 383 rows = 383 distinct pairs).
Verified: psql re-run clean; `./gradlew test` green (ImporterServiceTest re-imports twice).

## 16. schema.sql — check_results.status had no CHECK constraint [maintainability/medium]
Every other status column is constrained; this one accepted arbitrary text. Added
CONSTRAINT ck_check_results_status CHECK (upper(status) IN ('PASS','FAIL','NOT_ATTEMPTED','SKIPPED','INFRA'))
- the CheckStatus enum's values; upper() accepts the lowercase values legacy rows and the tests carry
(mirroring CheckStatus.parse). Deliberately no retro-fit heal for pre-existing DBs: PG has no
ADD CONSTRAINT IF NOT EXISTS and a DO $$ block would break ScriptUtils' ';' splitting used by the
app/tests; the live agentbench DB was verified to contain only valid values, so fresh-DB integrity
is the practical fix.
Verified: `./gradlew test` green.

## 17. schema.sql — all FKs were NO ACTION on DELETE [maintainability/medium]
Deleting an experiment with live jobs, or a run with check rows, failed with foreign_key_violation;
cleanup required manual orphaning. Fix: runs.job_id ON DELETE CASCADE, check_results.run_id ON
DELETE CASCADE (check rows die with their run; the importer's DELETE-by-run becomes a belt-and-
braces), jobs.experiment_id ON DELETE SET NULL (it is nullable - unpin, don't fail). For existing
DBs (CREATE TABLE IF NOT EXISTS cannot retrofit FK actions) a single-statement drop-and-re-add of
the PG auto-named _fkey constraints heals them idempotently across the per-startup re-run.
Verified: psql round-trip - delete experiment keeps job with NULL experiment_id; delete job cascades
to run and its check rows; `./gradlew test` green.

## 18. schema.sql — header claimed idempotency the file could not deliver [maintainability/medium]
Only CREATE TABLE IF NOT EXISTS existed: a partially-migrated DB could not be healed by re-running.
Now every statement form in the file is re-run safe (created across review points 12-17: IF NOT
EXISTS indexes/constraints, drop-and-re-add FKs). The header documents the three safe statement
forms and why PG's missing ADD CONSTRAINT IF NOT EXISTS forces the drop-re-add pattern (DO $$ would
break ScriptUtils' ';' splitting used by the app and the ITs).
Verified: psql double-apply clean (second run all NOTICE-skip); `./gradlew test` green.
