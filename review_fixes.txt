One section per review point, in the order processed. Each fix is followed by a full test

[baseline] Make the test suite green before starting the review fixes
────────────────────────────────────────────────────────────────────────────────
Files: Json.java, ServiceClient.java, application.yml, ServiceClientWireTest.java, review.txt

The working tree carried uncommitted changes (confirmed with the author as intentional):
Json.java disables Jackson FAIL_ON_NULL_FOR_PRIMITIVES because the service answers null
for booleans it cannot decide, ServiceClientWireTest gained a "poolable":null case, and
application.yml points back at the API server on 8765. The suite was red (2 failures):
the wire tests build their RestClient from the framework default, which uses its own
Jackson mapper, so the lenient setting in the shared Json.MAPPER never applied there.

Change: ServiceClient.build() now replaces the framework-default Jackson 3 converter
(JacksonJsonHttpMessageConverter) with one backed by the shared Json.MAPPER, honoring
the C-9 "one shared mapper" design; the converter is appended (not prepended) so
String/byte converters still win for String targets (plain-text file downloads).
Json.MAPPER's static type was narrowed from ObjectMapper to JsonMapper (the type the
Spring 7 Jackson 3 converter requires); all existing callers use inherited ObjectMapper
methods, so this is source-compatible.

Result: 140/140 tests pass.

────────────────────────────────────────────────────────────────────────────────
[1] md-viewer.css — responsive images with an explicit height attribute
     (src/main/frontend/styles/md-viewer.css)
────────────────────────────────────────────────────────────────────────────────
Added `height: auto` next to `max-width: 100%` on `.md-body img`. CommonMark emits
<img width=".." height=".."> attributes; without height:auto the pixel height is not
scaled down, so images overflow horizontally instead of keeping their aspect ratio.

Test run: 140/140 pass (CSS-only change; full suite run for good measure).

────────────────────────────────────────────────────────────────────────────────
[2] ExperimentDetailView.blockedReasons() — N+1 sequential HTTP calls
     (src/main/java/com/agentbench/ui/ExperimentDetailView.java)
────────────────────────────────────────────────────────────────────────────────
The per-blocked-job GET /api/jobs/{id} lookups now run on a bounded parallel
stream (ForkJoinPool.commonPool). The shared RestClient is immutable and
thread-safe, so the fetches no longer serialize 20+ round-trips on the UI
thread during render() / requeue-and-re-render. Encounter order is preserved
when folding into the LinkedHashMap, so tooltips and the joined reason line
display in the same order as before. Per-job failures are still tolerated
(tooltip simply absent).

────────────────────────────────────────────────────────────────────────────────
[3] ExperimentDetailView — String.join("\n") renders as one collapsed line
     (src/main/java/com/agentbench/ui/ExperimentDetailView.java)
────────────────────────────────────────────────────────────────────────────────
Browsers collapse consecutive whitespace (including newlines) in inline Span
content, so multiple blocked reasons ran together on one line. The blocked-line
span now sets white-space: pre-line, so each reason renders on its own line.

────────────────────────────────────────────────────────────────────────────────
[4] ExperimentNewView — NPE on auto-unboxing of un-checked checkboxes
     (src/main/java/com/agentbench/ui/ExperimentNewView.java)
────────────────────────────────────────────────────────────────────────────────
monoRules/par were never given an initial value; Vaadin Checkbox.getValue()
returns null until toggled, so if (checkbox.getValue()) threw an NPE on form
submit when the user never touched the box. Submit now uses
Boolean.TRUE.equals(...), which treats null as unchecked (the intended
default) and can never NPE.

────────────────────────────────────────────────────────────────────────────────
[5] ExperimentNewView — initial enabled-state desync for the parallel field
     (src/main/java/com/agentbench/ui/ExperimentNewView.java)
────────────────────────────────────────────────────────────────────────────────
The "parallel" IntegerField was interactively enabled (Vaadin default) while
the par checkbox it depends on starts unchecked; the value-change listener only
fires on subsequent toggles, so the user saw a live control that could not
affect the submission. Added parallel.setEnabled(false) at construction; the
existing par value-change listener syncs it from then on.

────────────────────────────────────────────────────────────────────────────────
[6] ExperimentParams.putIfPresent — type.cast escapes the IAE contract
     (src/main/java/com/agentbench/ui/ExperimentParams.java,
      src/test/java/com/agentbench/ui/ExperimentParamsTest.java)
────────────────────────────────────────────────────────────────────────────────
Values that are not already the target type (e.g. "0.5" for a Double) used to
escape as a raw ClassCastException, violating the Javadoc contract. The
normalizer now passes through type.isInstance(value), and otherwise parses the
toString() of the value: Boolean accepts "true"/"false" (anything else is
rejected), Double/Integer parse or reject, everything else is kept as text.
Parse failures surface as IllegalArgumentException with a named field, as
documented. Added a regression test
(sharedParams_parseStringValuesInsteadOfCasting).

────────────────────────────────────────────────────────────────────────────────
[7] ExperimentParams.build — null/blank template hit the switch and NPE'd
     (src/main/java/com/agentbench/ui/ExperimentParams.java)
────────────────────────────────────────────────────────────────────────────────
A null template used to fall into the switch expression and throw a bare
NullPointerException, violating the documented "@throws IllegalArgumentException
on bad input" contract (the sole caller only catches that type). An explicit
null/blank guard now rejects it with the same "unknown template: ..." message
as any other unknown template.

────────────────────────────────────────────────────────────────────────────────
[8] ExperimentsView — NPE when the experiment status is null
     (src/main/java/com/agentbench/ui/ExperimentsView.java,
      src/main/java/com/agentbench/ui/ExperimentDetailView.java)
────────────────────────────────────────────────────────────────────────────────
When experiment.status() is null, ExperimentStatuses.effective(...) returns the
raw value (null), so !effective.equals(...) threw an NPE and broke the whole
grid render, even though every other consumer treats status as nullable. Both
spots now use Objects.equals: the status-badge tooltip in ExperimentsView and
the identical latent pattern in ExperimentDetailView.render().

────────────────────────────────────────────────────────────────────────────────
[9] ExperimentsView — status column sorted by the raw table status
     (src/main/java/com/agentbench/ui/ExperimentsView.java)
────────────────────────────────────────────────────────────────────────────────
The cell renders the derived effective status (queued → running/blocked from
the jobs) but the comparator sorted by the raw table status, so clicking the
header produced visibly unsorted badges. The comparator now maps each row to
the same ExperimentStatuses.effective(...) the badge renders (nulls-last,
matching the previous null handling).

────────────────────────────────────────────────────────────────────────────────
[10] FilesBrowser — case-sensitive extension match misclassified README.MD
     (src/main/java/com/agentbench/ui/FilesBrowser.java)
────────────────────────────────────────────────────────────────────────────────
TEXT_SUFFIXES is lowercase but the matched suffix kept the file's original
case, so README.MD / CONFIG.JSON were treated as binary and linked to the raw
URL instead of the text viewer. isText now lowercases (Locale.ROOT, to dodge
the Turkish-İ locale bug) before the set lookup.

────────────────────────────────────────────────────────────────────────────────
[11] GroupsView — API data fetched once per session, never refreshed
     (src/main/java/com/agentbench/ui/GroupsView.java)
────────────────────────────────────────────────────────────────────────────────
Vaadin caches @Route instances per session, so render()-in-constructor meant
the leaderboard was fetched exactly once and went stale. Replaced the
constructor render() with addAttachListener(e -> render()), matching the
sibling views ExperimentsView and JobsView, so every navigation re-fetches.
