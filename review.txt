──────── Project Summary ────────

### Top Issues

1. **Schema lacks indexes on hot query paths and critical constraints** (`src/main/resources/schema.sql`)
   The `jobs(status, priority, id)` index is absent, so every worker `claim()` performs a full table scan. A second missing index on `jobs.experiment_id` serial-scans on each experiment detail view. Additionally, `jobs.run_id` has no `UNIQUE` constraint, leaving a TOCTOU race (two concurrent enqueues both pass the `SELECT count(*)` guard and insert duplicates). At scale this is both a performance and a correctness defect.

2. **`gradle.properties` hardcodes a machine-specific JDK path** (`gradle.properties`)
   An absolute Homebrew path to OpenJDK 21 is committed. Any developer or CI runner without that exact path gets an immediate build failure. This blocks all other contributors until fixed.

3. **Docker shim silently falls through on failure and has no concurrency guard** (`src/main/resources/docker_shim.sh`)
   If all 90 poll iterations expire (Docker Desktop absent, app crash, OOM), the script *unconditionally* `exec`s the real `docker` binary, producing a confusing downstream error instead of a clear diagnostic. Separately, N parallel `docker build` invocations each spawn an independent `open -a Docker` + 180 s poll loop with no `flock`, multiplying wasted resources.

4. **Duplicate Spring Boot version pins** (`build.gradle.kts`)
   The plugin version and the BOM `platform(...)` are declared independently at `3.5.5`. A partial upgrade changes one but not the other, silently producing a mismatched classpath with no build error.

5. **`.dockerignore` omits credential and IDE files** (`.dockerignore`)
   No exclusion for `.env`, `.env.local`, or `*.env.*`. If a developer adds a credentials file to the project root, the entire context (including secrets) is uploaded to the Docker daemon and baked into the image layer. IDE artifacts (`.idea/`, `*.iml`) are also included unnecessarily.

6. **All foreign keys default to `NO ACTION` on DELETE** (`src/main/resources/schema.sql`)
   Deleting an experiment fails if any job references it; deleting a run fails if check_results exist. The schema makes normal cleanup impossible without manual orphaning or manual `DELETE` of children first.

7. **Recursion guard is over-broad** (`src/main/resources/docker_shim.sh`)
   The shim refuses to run if `AB_DOCKER_SHIM` is set to *any* non-empty value, including `0` or values set by unrelated parent tooling. This silently disables the shim in CI or wrapper scripts that happen to export the variable for a different purpose.

8. **`CI=1` env var leaks to all Test tasks** (`build.gradle.kts`)
   `tasks.withType<Test> { environment("CI", "1") }` applies the variable to every test task in the project, not just the intended `dockerTest`. Any library code that branches on `CI` will see it in unit tests, integration tests, and Spock/JUnit runs alike.

9. **Gradle wrapper download has `retries=0`** (`gradle/wrapper/gradle-wrapper.properties`)
   A single transient network blip during the ~200 MB distribution download hard-fails the build. One character change (`1` or `2`) eliminates a common flaky-CI source.

10. **Schema file claims idempotency but cannot handle schema evolution** (`src/main/resources/schema.sql`)
    The header states re-runs must upsert and never fail, yet only `CREATE TABLE IF NOT EXISTS` is used. No `CREATE INDEX IF NOT EXISTS`, no constraint migrations, no `ALTER` guards—so adding a new index or column in a later release will crash the importer on re-run.

### Cross-Cutting Concerns

- **Missing defensive failure handling / silent fallthrough.** `docker_shim.sh` skips the daemon without an error if the poll loop expires; `schema.sql` claims idempotent upserts but has no mechanism to handle partial migrations; `build.gradle.kts` pins two version strings that can silently diverge. In each case the *happy path* works but the *failure path* is either absent or misleading.

- **Concurrency safety gaps.** The DB has a `SELECT count(*)` TOCTOU race on `run_id`; the shell shim has no inter-process lock for parallel invocations; the `CI=1` env var has uncontrolled blast radius. Three different files independently assume single-threaded or single-process execution where that assumption doesn't hold.

- **Machine-specific / environment-specific values committed to shared files.** Hardcoded Homebrew JDK path (`gradle.properties`), missing `*.iml` and `local.properties` in `.gitignore`, missing `.env` in `.dockerignore`. The repo has no clear boundary between "shared config" and "local developer config."

- **Redundant or dead declarations.** `testImplementation("org.postgresql:postgresql")` is redundant because `implementation` already extends to the test classpath; H2 as `testRuntimeOnly` appears to serve no active test. These add cognitive noise and can mask classpath misconfiguration.
