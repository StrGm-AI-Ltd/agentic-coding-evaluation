| 4 | **File-descriptor and stream leaks in hot paths** – `Tailer.poll()` opens a `Files.list` stream every 2 s and never closes it; `VerifyTask` can skip `log.close()` on mid-loop IOException; `ReferenceServer.stop()` never shuts down its thread pool; `RecordingProxyFactory` abandons a half-started proxy. | FD exhaustion, thread-pool leak, container OOM over time | `service/Tailer.java`, `runner/VerifyTask.java`, `reference/ReferenceServer.java`, `runner/RecordingProxyFactory.java` |
| 5 | **Object allocation inside hot loops** – a new `ObjectMapper` per tool-call parse (up to 400 turns × N calls), `Pattern.compile` per line, `DocumentBuilderFactory.newInstance()` per XML file, a fresh `EnumSet` per record in a stream filter. | GC pressure and CPU waste at benchmark scale | `agent/ReferenceAgent.java`, `runner/VerifyTask.java`, `oracle/CheckId.java` |

| 10 | **`ReferenceServer` never calls `reply()` for unrecognised sub-paths** – a 3+-segment path that isn't `/holdings` falls through without sending any HTTP response, leaving the client hanging. ### Cross-Cutting Concerns

1. **Null-safety against Jackson / JSON inputs** – `path("…").get(0)` without a `MissingNode` guard, `Map.of` with nullable values, `getOrDefault` that still returns `null` when the key is present-but-null, `getResourceAsStream` returning `null`. This pattern recurs in at least **9 files** (`AgentSession`, `AgentTools`, `Collect`, `RunOracle`, `CheckStatus`, `SseAssembler`, `BenchController`, `RunBenchTest`, `ReferenceServer`).

2. **Resource lifecycle not closed** – `Stream<Path>` from `Files.list`, `HttpServer` + cached thread pool, `FileWriter`/`FileOutputStream`, temp directories in tests. No use of try-with-resources in the leaky sites. Affects `Tailer`, `ReferenceServer`, `RecordingProxyFactory`, `VerifyTask`, and several test classes.

3. **Dead code that obscures intent** – unused method parameters (`AgentSession`), never-called public methods (`RunBenchSupport.killTree`, `gradleHome`), unused constants (`TERMINAL_PROXY_STATES`), unused local variables in tests. 6+ occurrences across 5 files. The dead `killTree` also contains a *latent* bug (checks `commandLine()` for an env-var value), making it doubly dangerous.

4. **Object creation inside loops / hot paths** – `ObjectMapper` (per tool call), `Pattern.compile` (per line), `DocumentBuilderFactory` (per file), `EnumSet` (per record). No caching or reuse.

5. **Inconsistent or overly-broad exception handling** – catching `IllegalArgumentException` when the real exception is `DateTimeException`/`IndexOutOfBoundsException`; `catch (IOException ignore)` that prevents a `finally` close; silent `catch (Exception)` returning a sentinel. Appears in `ReferenceServer`, `VerifyTask`, `TreatmentPin`, `CheckStatus`, `SseAssembler`.

### Quick Wins

| Fix | Effort | Leverage |
|-----|--------|----------|
| Replace `Map.of(…, ternary)` with `Map.entry` + `HashMap` (or a null-check) in `Collect.java` and `RunOracle.java` | 15 min | Prevents hard crashes of the entire scoring pipeline |
| Add a `USER nonroot` directive + a `USER` line to the `Dockerfile` runtime stage | 5 min | Closes the root-in-container finding |
| Hoist `Pattern.compile` and `DocumentBuilderFactory` to `static final` / method-local in `VerifyTask.java` | 10 min | Eliminates per-line / per-file allocation in the hottest verification loop |
| Wrap `Tailer.poll()`'s `Files.list` in try-with-resources; add offset-reset when `size < start` | 10 min | Stops FD leak in a 2 s polling loop; restores tailing after rotation |
| Delete dead code: `RunBenchSupport.gradleHome()`, `killTree()`, `RecordingProxyFactory.TERMINAL_PROXY_STATES`, unused `AgentSession` params, unused `req` in `AgentToolsTest` | 15 min | Removes 6 misleading symbols; eliminates a latent bug (`killTree`) from the API surface |
| Add `finally { log.close(); }` in `VerifyTask` and store/shutdown the executor in `ReferenceServer.stop()` | 10 min | Closes two of the most likely FD / thread leaks |
| In `JobQueue`, replace check-then-act with a single conditional `UPDATE … WHERE id = ? AND status = 'queued'` and check `getUpdateCount()` | 20 min | Eliminates the race without adding locks or new DB round-trips |

Each of these is a ≤ 30-minute change with a clear correctness or stability payoff, and none requires an architectural redesign.
