# L3p — Orders and point-in-time holdings, planned (budget 90 min: 15 min plan + 75 min implementation)
Build a service on `localhost:8080` (via `docker compose up`, with PostgreSQL) exposing: `POST /accounts` → 201 `{accountId, currency, availableBalance}`; `GET /accounts/{id}` → 200 `{accountId, currency, availableBalance, reservedBalance}`; `POST /accounts/{id}/deposits` `{"amount"}` → 200 `{availableBalance}`; `POST /orders` `{accountId, symbol, side:"BUY"|"SELL", quantity:"5", limitPrice:"10.00"}` → **201** `{orderId, status:"FILLED", executedAt}` (immediate fill at `limitPrice`; balance debited/credited by quantity × limitPrice) or **422** on insufficient funds/holdings; `GET /accounts/{id}/holdings?asOf=<ISO-8601>` → 200 `{holdings:{SYM:"qty"}, asOfApplied}`; `GET /health` → 200. The replay must **subtract** sells; a buy then an equal sell restores balance and holdings exactly. Symbols: `AAPL`, `TSLA`, `EURUSD`.
**Bespoke rules:** (1) the `asOf` boundary is **exclusive** — an order executed at exactly T is NOT included in `asOf=T`; (2) `asOfApplied` is always present and echoes the instant actually applied (or "now" when `asOf` is absent), normalised to UTC milliseconds with a trailing `Z`.
All money is `BigDecimal` or integer minor units — never float/double. Decimal JSON values are strings; timestamps are ISO-8601 UTC with millisecond precision (`2026-01-31T12:00:00.123Z`). Java 21, Spring Boot 3, Gradle, PostgreSQL via Flyway. Ship tests that run with `gradle test` in a clean container: a fresh PostgreSQL is provided through `SPRING_DATASOURCE_URL/USERNAME/PASSWORD` (tests may use it or run in memory; they must not need Docker or the network). **Packaging is graded from source:** the grader runs `docker compose build` on a clean checkout that contains NO build outputs (no `build/`, `target/`, `dist/`, no committed `.jar`/`.class` files). Every image must therefore build the application inside the image (e.g. a multi-stage Dockerfile with a Gradle build stage); a Dockerfile that `COPY`s a jar or bundle built on the host fails the runtime checks. Do not edit anything under `task/`. **This rung starts from an empty workspace: everything it names must be built here.**
**Protocol for this rung:** first write `docs/IMPLEMENTATION_PLAN.md` — 3–6 ordered subtasks with ids (T1, T2, …), each with a goal, affected services, dependencies and a verifiable acceptance criterion — and no code. The implementation phase then follows the plan.
